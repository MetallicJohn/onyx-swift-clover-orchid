# CR-031 Traffic monitoring

Native four-tier telemetry on the existing ISP Solutions console. Not a separate monitoring app.

- **A Realtime** — Redis live keys (`traffic:live:{tenant}:{username}`) with TTL. Never written to PostgreSQL per sample.
- **B Short-term** — Redis ring (capped) plus `traffic_minute` (1-minute buckets, short retention).
- **C Aggregates** — `traffic_hourly` / `traffic_daily` plus `router_metrics` / `interface_metrics`. Idempotent upserts.
- **D Billing** — unchanged RADIUS accounting → `services.bundle_used_mb`. Collectors do not scan samples for usage.

Customer/service mapping uses stable IDs (RADIUS username, service username, static IP). Unmapped sessions are skipped and logged, never attributed.

MikroTik collection is batched REST (`/system/resource`, `/interface`, `/ppp/active`) per router, not per customer. SNMP and NetFlow adapters return `not_configured` and invent no values.

UI: existing customer traffic drawer (rates, duration, last seen, router, hourly chart) and a router monitoring panel. Platform settings control intervals and retention.

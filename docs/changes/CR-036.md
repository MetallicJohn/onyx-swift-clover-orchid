# CR-036 Services desk redesign

`/app/services` is now a paged operations desk instead of a client-filtered dump of every live line.

| Surface | Behaviour |
|---|---|
| Search | Server-side across service ID, customer name, account, phone, email, PPPoE/hotspot username, static IP, framed IP, MAC, package, router, location |
| Filters | Status (including derived Expired), access type, package, customer, location, router, IP pool, billing, expiring soon, grace, overdue. VLAN/AP/service tags are omitted because they are not in the schema. |
| Counters | Tenant totals: all, active, pending, expired, suspended, grace |
| List | Compact table on desktop; stacked cards on mobile. Customer name opens the profile. Service ID opens the existing service record. |
| Actions | Dropdown grouped by record / credentials / lifecycle. Expiry, grace, reassign, Recycle Bin, traffic, and package change reuse the existing APIs. |
| Preview | Right-side drawer loads `getServiceFn`. Does not replace the service record. |
| Traffic | Existing `TrafficDrawer` scoped to the selected service. No invented values. Session column is last RADIUS accounting only. |
| Delete | Recycle Bin (`deleteServiceFn`). Customer and sibling services stay. Recycled rows stay out of search. |
| Bulk | Suspend, restore, grace, package change, retry PPPoE, export, SMS through existing communications. Confirmation required. |
| Status | Expired is derived from a past access date on a non-live line, and is not the same as Suspended or Grace Period. |

`listServices` is unchanged for other callers. Proof: `service-desk.test.ts`.

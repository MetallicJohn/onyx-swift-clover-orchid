# CR-051 Zero data-loss production updates

Production ISP data is treated as persistent business state. Application images are replaceable; Docker volumes and Postgres rows are not.

| Guard | Behaviour |
|---|---|
| Backup | Custom `pg_dump` before every update when a `pgdata` volume exists. File must exist, be non-tiny, start with `PGDMP`, and pass `pg_restore --list`. |
| Scan | Pending migrations with `DROP TABLE` / `TRUNCATE` / `DROP COLUMN` / `DELETE FROM` stop the deploy. Historical allowlist: `0023_empty_tenants_created_today.sql` only. |
| Lock | `flock` on the update script plus `pg_advisory_lock` in `migrate.mjs`. |
| Counts | Pre/post snapshots of tenants, customers, services, invoices, payments, routers, and related tables. A decrease is manual review. |
| Rollback | Health failure rolls **git/code** back. The live database is not auto-restored. |
| Restore | Requires `--i-understand-this-overwrites-live-data`. |
| Volumes | `docker compose up -d --build` only. `down -v` is refused. |
| Seed | `NODE_ENV=production` never auto-empties `demo_seeded` tenants. Existing WireGuard keys are not regenerated. Env secrets are append-only. |

Proof: `migration-safety.test.mjs`, `data-integrity.test.mjs`, `deploy-protect.test.mjs`, `empty-tenant.test.ts`, `access.test.ts`. Procedure: [disaster-recovery.md](../disaster-recovery.md).

# CR-035 Customers desk redesign

`/app/customers` is now a paged operations desk instead of a client-filtered dump of the whole tenant.

| Surface | Behaviour |
|---|---|
| Search | Server-side across name, account number, phone, email, location, service ID, PPPoE/hotspot username, static IP |
| Filters | Customer status, service status, access, package, location, billing, expiring soon, grace, overdue, tags. Active chips clear one at a time. |
| Counters | Tenant totals: all, active (live line), suspended, overdue |
| List | Compact table on desktop (name, account, phone, package, type, status, expiry, last activity, outstanding). Stacked cards on mobile. Name opens the existing profile. |
| Actions | Dropdown grouped by record / services / billing / ops. Add service and view tabs land on `/app/customers/$id?tab=…`. |
| Preview | Right-side drawer loads `getCustomerFn` (real services, payments, balance). Does not replace the profile. |
| Traffic | Existing `TrafficDrawer` / RADIUS collector. No invented values. |
| Delete | Recycle Bin (`deleteCustomerFn`). Recycled rows stay out of search. |
| Bulk SMS | Recipient count from valid unique Kenya mobiles; missing/invalid/duplicate skipped. |
| Status | Derived: a customer is not Active unless a live (active/grace) service exists. Same rule on the profile header. |

`listCustomers` is unchanged for statements. Proof: `customer-desk.test.ts`.

# CR-045 Public domain resolution

ISP Solutions resolves every public URL from a real, configured domain. Generated RouterOS scripts never contain `YOUR-PUBLIC-URL`, `{{BOOTSTRAP_URL}}`, localhost, or an internal hostname in production.

| Surface | Behaviour |
|---|---|
| Resolver | Verified custom domain → verified tenant subdomain → central `app.public_url` / `APP_PUBLIC_URL`. Unverified, expired, revoked, or disabled names are skipped. Missing config throws and does not invent a host. |
| Central domain | Platform setting `app_public_url` (env fallback). Used for all ISPs when no tenant domain is verified, and in central-domain-only mode. |
| Subdomain | `{slug}.{tenant_subdomain_base}`, reserved labels rejected. Active only after DNS and HTTPS checks. Unverified subdomain falls back to central with a warning. |
| Custom domain | Pending → DNS → HTTPS → active. TXT (`_isp-solutions-verification…`) or CNAME/A to the platform. Certificate must be trusted, unexpired, and match the hostname. |
| Bootstrap | Server resolves the origin, inserts the token, quotes the URL, and always uses `mode=https check-certificate=yes`. No domain → no script. |
| UI | Platform **Domains**: central URL, per-ISP subdomain/custom, verify DNS/HTTPS, disable/revoke/remove, test URL. Routers desk shows the domain source and exact fetch URL before paste. |
| Isolation | Unique hostname globally. RLS on `tenant_domains`. Platform-only verification. Audit `platform.domain.*`. |
| Links | `resolveTenantPublicUrl` is used for portal, payment, SMS, email, and webhook callback origins. |

Scenarios: central-only, verified subdomain, unverified subdomain fallback, verified custom, unverified custom ignored, expired cert retired, revoked/removed, tenant isolation, development localhost only in preview, missing domain refuses the script.

Proof: `domain-format.test.ts`, `domain-verify.test.ts`, `domain-resolve.test.ts`, `domain-manage.test.ts`, `router-provisioning.test.ts`.

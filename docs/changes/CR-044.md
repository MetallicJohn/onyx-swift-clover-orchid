# CR-044 GenieACS device management

The GenieACS page is a device desk, not a register-CPE form. Staff add, assign, and act on CPE/ONU devices through the existing GenieACS NBI, `cpe_devices`, and `acs_tasks`.

| Surface | Behaviour |
|---|---|
| Devices tab | Title **GenieACS Devices**, Add Device on load, search, filters (status, online, assigned, vendor, model, type, customer, service, location), compact rows, actions menu, optional 30s auto-refresh. Empty list still shows Add Device. Discovery is never invented. |
| Add Device | From GenieACS (unassigned), manual serial (stored as unknown / not confirmed), or wait for the next Inform. Manual devices are not marked online. |
| Assignment | Search customer or service (name, phone, email, accounts, username, IP). Radio select of the exact service. Confirm checkbox. Reassign needs an extra confirm. One CPE per service. Tenant-only. No SMS, invoice, or billing change. |
| Actions | View, refresh, Inform, reboot (confirm), factory reset (type RESET), Wi-Fi (review + verify SSID), optical (vendor paths; missing → “not exposed”), tasks/retry, assign/unassign. Firmware upgrade is unsupported until a file server exists. NBI accept is not success. Offline → waiting for Inform. |
| RBAC | `acs.devices.*` / `acs.tasks.*`. Network engineer: full control. Customer care: view/add/assign. Technician/support: view + optical. Finance: none. `/app/acs` uses `acs.devices.view`. |

Audit: `acs.device.assigned` / `reassigned` / `unassigned` / `wifi.updated` / `reboot` / `factory_reset` / `inform` / `acs.task.retry`. Wi-Fi passwords are sealed and never logged.

Proof: `acs-device-format.test.ts`, `acs-devices.test.ts`, `acs-device-actions.test.ts`, `acs.test.ts`, `rbac.test.ts`.

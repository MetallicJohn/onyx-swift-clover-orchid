# CR-049 Compact routers desk and per-router IP pools

The Routers page is a summary list. Details, IP pools, and monitoring load only after a router is opened.

| Surface | Behaviour |
|---|---|
| List `/app/routers` | Name, identity, management IP, model, status, last seen, site, pool count, active service count. Search and filters are server-side and debounced. Pagination 50. No per-row config, pools, or charts. |
| Details `/app/routers/:id` | Opens from the name or Details. WireGuard public key and overlay only — no private keys, enroll tokens, or API passwords. |
| IP pools | Created against the selected router. CIDR, gateway, range, VLAN, access type, duplicate name/code, and tenant overlap are validated. In-use range changes need confirmation and cannot drop assigned addresses. Archive is blocked while services still use the pool. |
| Monitoring | Hidden until **Show monitoring**. Polling stops on **Hide monitoring**. Values come from stored collector samples only. |
| Permissions | `routers.read` for list and details. `routers.manage` for create/edit/sync/test/pools/archive. Suggested names such as `routers.ip_pools.*` map to these existing keys. |

Not changed: MikroTik bootstrap (`check-certificate=yes`), RADIUS, billing, ACS, RLS.

Proof: `router-desk.test.ts`, `router-desk-format.ts`, `ipam.ts`.

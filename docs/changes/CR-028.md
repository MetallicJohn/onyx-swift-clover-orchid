# CR-028 Distributed deployment architecture

Prepare the existing ISP Solutions app so PostgreSQL, Redis, FreeRADIUS, GenieACS/Mongo, workers, and traffic collectors can move to separate VPS servers by changing environment variables and Compose files. Product workflows and public APIs stay the same.

- Validated `runtime-config` forbids localhost fallbacks in production.
- Adapters: Redis (optional), Postgres job queue, traffic collector, health/ready probes.
- Internal service APIs `/api/internal/jobs` and `/api/internal/traffic` (Bearer `INTERNAL_SERVICE_TOKEN`). Caddy returns 404 for `/api/internal*` on the public site.
- Durable jobs live in Postgres (`job_queue`). Redis is cache/lock only; billing and RADIUS keep working if Redis is down.
- Traffic collector snapshots `radius_sessions` into `traffic_samples`. The customer traffic panel still reads live accounting and never invents values.
- Compose roles: `compose.single-vps.yml` (alias of `docker-compose.yml`), `compose.application.yml`, `compose.database.yml`, `compose.network-services.yml`, `compose.traffic-collector.yml`, `compose.workers.yml`.
- Thin `worker.mjs` / `collector.mjs` poll internal APIs so the VPS image (`.output` only) does not import `src/`.
- Migrations stay separate from process start (`SKIP_MIGRATE=1` on workers).

See [docs/distributed.md](../distributed.md).

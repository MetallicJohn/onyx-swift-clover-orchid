# CR-038 MikroTik router provisioning

Routers is a provisioning desk on the existing agent + WireGuard stack. It does not replace enroll tokens or overlay peers.

| Surface | Behaviour |
|---|---|
| Add / update / delete | Name, identity, RouterOS version, model, site/POP, management IP, role. Overlay IP is unique per ISP. Delete removes tokens, versions, events, and pool assignments. |
| Bootstrap | Short RouterOS v7 paste: ping 1.1.1.1 / 8.8.8.8, then `/tool fetch` the router-specific `.rsc` over HTTPS with `check-certificate=yes`. Certificate validation is never disabled. |
| Token | `prv_` + 32 random bytes (base64url). SHA-256 stored; hint is last 4 characters. TTL from superadmin ISP settings (default 72h). Revoke clears the hash. Fetch after revoke is 404. |
| Generated `.rsc` | Validated enroll (WireGuard + agent pull) plus assigned `/ip pool` entries. Stored as configuration versions. Users cannot submit arbitrary RouterOS. |
| Status | `pending` → `awaiting_bootstrap` → `bootstrapping` after a successful fetch. `wg_status` stays `pending` until agent heartbeat/pull. Online is never claimed without `last_seen`. |
| IP pools | Create CIDR pools on Routers, assign them on the router record, and push `pool.push` to the agent. |
| APIs | `GET/POST /api/routers`, `GET/PATCH/DELETE /api/routers/{id}`, `POST .../provisioning-token`, `POST .../revoke-token`, `GET .../status`, `GET .../configuration-history`, `POST .../pools`, `GET /api/vpn/routers/{token}/bootstrap.rsc`. Authenticated routes use the operator session. Provisioning endpoints are rate-limited. |
| Superadmin | Per-ISP: enable, token TTL, require HTTPS, allow pool push. |

Proof: `router-provisioning.test.ts`, `mikrotik.test.ts`. Live kernel handshake is not run in CI.

# CR-037 Secure customer portal

The existing `/portal` surface is a customer workspace on the same billing, payments, tickets, and auth stack. It is not a separate app.

| Surface | Behaviour |
|---|---|
| Login | Phone is the username. The same phone is the first password (hashed, country-normalised). Change is recommended on first login, not required. SMS OTP reset remains. OTP values are not returned to the browser except as a sandbox instruction. |
| Dashboard | Account status, service counts, outstanding, next renewal, latest payment, unpaid invoices, open tickets, Pay now |
| My services | Package, price, billing period, renewal, expiry, status, payment status. No speeds, type, location, description, or credentials |
| Pay | Enabled and complete tenant methods only. M-Pesa STK confirms via callback/poll, not the initial request. Idempotent pending intents |
| Payments / invoices | Own records only. PDF/statement ownership checked before generation. Customer-safe documents (masked references, no technical copy) |
| Tickets | Customer categories, replies. Internal staff notes excluded |
| API | Versioned `/api/v1/portal/:action` with bearer portal session for future Android/iOS clients |

Proof: `customer-portal.test.ts`. Native apps not built.

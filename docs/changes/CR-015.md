# CR-015 custom domain sign-in origin

Better Auth was rejecting email/password POSTs from a custom domain with `Invalid origin` because `trustedOrigins` only listed `BETTER_AUTH_URL` (usually the platform host) and loopback.

Per-request trusted origins now include:

- The request Origin when it matches `Host` / `X-Forwarded-Host` (same-origin; CSRF still blocked)
- Each tenant `public_base_url` (www and apex)
- `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_URL`, `BETTER_AUTH_TRUSTED_ORIGINS`

CSRF is not disabled. Sibling `*.grok.me` apps are still untrusted. Google/X broker callbacks stay on `BETTER_AUTH_URL`. Password-reset links use the forwarded public origin.

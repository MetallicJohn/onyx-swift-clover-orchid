# MILESTONE — ENQUIRIES & LEADS CRM

## Objective

Implement **Enquiries & Leads as a core CRM milestone** in the existing ISP SaaS application.

Do NOT rebuild the existing CRM or Customer module.

The existing application already has Customers, Services, Packages, Billing, and related ISP functionality. Extend the current architecture and reuse existing components, authentication, tenant context, database conventions, UI patterns, permissions, audit logging, and migrations.

The key business rule is:

> **A Lead is NOT a Customer.**

Leads must not increase customer counts, active customer counts, revenue customer metrics, customer reports, or service/customer statistics until the lead is successfully converted into a real Customer after the installation/activation process.

---

# 1. Navigation

Place the new module under:

```text
Customers
├── Customers
└── Leads
```

Do not create a completely separate top-level Sales/CRM menu unless the existing application architecture requires it.

The primary page should be:

```text
Customers → Leads
```

The Leads page should have an:

```text
+ Add Lead
```

button.

Clicking **Add Lead** must open a dialog/modal rather than navigating to a separate page.

### Important

Do NOT automatically create a Customer simply because a Lead is created.

Do NOT count Leads as Customers.

A Lead becomes a Customer only after the configured conversion requirements are satisfied.

# 3. Lead → Customer conversion

The core workflow must be:

```text
Lead
  ↓
Installation completed
  ↓
Lead confirmed
  ↓
Convert
  ↓
Existing Customer check
  ↓
Create/reuse Customer
  ↓
Create Service
  ↓
Transfer relevant lead information
  ↓
Mark Lead as Converted
```

The Lead record must remain in the database after conversion for historical and reporting purposes.

Do NOT delete the Lead.

Add fields such as:

```text
converted_at
converted_by
customer_id
service_id
conversion_status
```

Example:

```text
Lead #LD-000123
       ↓
Customer #CUS-001245
       ↓
Service #SRV-001890
```

Maintain these relationships permanently.

# 4. Prevent duplicate customers

Before conversion, perform a duplicate check using appropriate existing customer identifiers.

At minimum check:

- Phone number
- Alternative phone number
- Email where available
- National/company identifier if the existing Customer model supports it
- Name + phone combination

If a matching customer exists:

```text
Existing Customer Found
```

show the user the matching customer and allow:

```text
Use Existing Customer
```

rather than creating a duplicate.

If no customer exists:

```text
Create New Customer
```

# 7. Location / GPS coordinates

This is an important ISP-specific requirement.

The Add Lead dialog must contain a **Location** section.

Fields:

```text
Latitude
Longitude
```

Use appropriate numeric validation.

Example:

```text
Latitude: 0.016947
Longitude: 37.072811
```

Add a convenient:

```text
📍 Get Current Location
```

button where browser/device geolocation permission is available.

When clicked:

```text
Browser Geolocation API
        ↓
latitude
longitude
        ↓
populate form
```

Do not silently obtain location without user action/permission.

Also provide:

```text
Select on Map
```

if a map component already exists or can be added without introducing unnecessary infrastructure.

The user should be able to manually edit the coordinates.

### Validation

Latitude:

```text
-90 to +90
```

Longitude:

```text
-180 to +180
```

Store coordinates as proper numeric/decimal values, not concatenated text.

Recommended database fields:

```text
latitude
longitude
```

Use sufficient precision for ISP field operations.

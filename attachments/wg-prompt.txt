# ISP Solutions — Complete WireGuard-to-MikroTik Connection Flow Rewrite

Rewrite the **entire ISP Solutions WireGuard connection flow between the VPS and MikroTik**, including backend provisioning logic, RouterOS script generation, enrollment, editing existing MikroTik routers, connection verification, agent configuration, and the frontend script-generation dialogs.

This is a **full replacement of the current WireGuard/MikroTik enrollment flow**.

Do not patch the existing implementation piecemeal. First inspect the current implementation, then replace the relevant WireGuard/MikroTik provisioning flow with one coherent implementation.

Do not change unrelated ISP Solutions functionality.

---

# 1. Target Architecture

Implement this architecture:

```text
                         INTERNET
                            |
                            |
                  wg.ispsolutions.co.ke
                            |
                    UDP 51820 / VPS
                            |
                  +-------------------+
                  | ISP Solutions VPS |
                  |                   |
                  | WireGuard Hub     |
                  | 10.200.0.1        |
                  |                   |
                  | ISP Solutions App |
                  |                   |
                  | Router API        |
                  | Agent Controller  |
                  +---------+---------+
                            |
                     WireGuard tunnel
                            |
                  10.200.x.x/32
                            |
                   +--------+--------+
                   |    MikroTik    |
                   | RouterOS v7    |
                   |               |
                   | wg-ispsolutions|
                   | 10.200.x.x/32  |
                   |               |
                   | API TCP 8728   |
                   +----------------+
```

The VPS is the WireGuard hub.

Each MikroTik is a WireGuard peer.

Each MikroTik receives a unique overlay address:

```text
10.200.x.x/32
```

The VPS/controller uses:

```text
10.200.0.1
```

The MikroTik WireGuard peer must use:

```text
allowed-address=10.200.0.1/32
```

The MikroTik API must be reachable only through the WireGuard management network.

# 2. Public Endpoints

Use:

```text
Web:
https://ispsolutions.co.ke

WireGuard:
wg.ispsolutions.co.ke:51820
```

The WireGuard DNS record must point to the VPS public IP and remain **DNS-only**, not Cloudflare-proxied.

Do not use:

```text
ispsolutions.co.ke
```

as the WireGuard endpoint.

Do not attempt to proxy UDP 51820 through normal Cloudflare HTTP proxying.

# 3. No MikroTik Certificate Dependency

This requirement is mandatory.

The MikroTik connection flow must **not depend on the MikroTik CA store**.

Do not:

* Install a CA certificate.
* Generate a MikroTik certificate.
* Import certificates.
* Configure certificate validation.
* Require `check-certificate=yes`.
* Require RouterOS API-SSL.
* Require HTTPS certificate trust on RouterOS.

RouterOS bootstrap/agent HTTPS must use:

```routeros
check-certificate=no
```

The secure management channel is:

```text
WireGuard → RouterOS API
```

Do not replace this with certificate-based RouterOS management.

# 11. MikroTik WireGuard Configuration

Generate:

```routeros
/interface wireguard
```

with:

```text
name=wg-ispsolutions
```

and the router-specific private key.

Example:

```routeros
:if ([:len [/interface wireguard find where name="wg-ispsolutions"]] = 0) do={

    /interface wireguard add \
        name="wg-ispsolutions" \
        listen-port=13231 \
        private-key="<ROUTER_PRIVATE_KEY>" \
        comment="ISP Solutions";

} else={

    /interface wireguard set \
        [find where name="wg-ispsolutions"] \
        private-key="<ROUTER_PRIVATE_KEY>" \
        listen-port=13231 \
        comment="ISP Solutions";
}
```

Do not blindly rename arbitrary existing WireGuard interfaces.

# 15. API Firewall

Create/reconcile:

```routeros
/ip firewall filter
```

allowing only:

```text
source = 10.200.0.1
interface = wg-ispsolutions
protocol = tcp
port = 8728
```

Example:

```routeros
/ip firewall filter add \
    chain=input \
    in-interface="wg-ispsolutions" \
    protocol=tcp \
    src-address=10.200.0.1 \
    dst-port=8728 \
    action=accept \
    comment="ISP Solutions api";
```

Do not create a WAN API access rule.

# 19. Agent Fetch

The agent must fetch:

```text
https://ispsolutions.co.ke/api/agent/script
```

using its router-specific credential/token.

Use:

```routeros
check-certificate=no
```

The fetch implementation must capture the actual RouterOS result.

Example:

```routeros
:local result [/tool fetch \
    url=$fetchUrl \
    mode=https \
    check-certificate=no \
    http-method=get \
    output=file \
    dst-path="ispsolutions-pull.rsc" \
    as-value];

:local status ($result->"status");
:local code ($result->"code");
:local downloaded ($result->"downloaded");
```

A successful result:

```text
status=finished
HTTP=200
downloaded > 0
```

must be treated as success.

Never report:

```text
HTTPS fetch failed
```

after:

```text
Download ... FINISHED
```

# ISP Solutions — Complete RouterOS v7 Agent Implementation

Implement the complete ISP Solutions RouterOS v7 enrollment and persistent-agent system.

This implementation must produce a **complete, production-ready RouterOS v7 configuration script** that can be pasted into MikroTik **New Terminal** or imported as an `.rsc` file.

The implementation must also correct the current false error:

```text
Download from ispsolutions.co.ke FINISHED
ISP Solutions: HTTPS fetch failed check URL and internet
```

A `FINISHED` download must **not** be treated as a fetch failure.

---

# 1. Critical Architecture

Use this architecture:

```text
MikroTik RouterOS v7
        |
        | WireGuard UDP 51820
        v
wg.ispsolutions.co.ke
        |
        v
ISP Solutions VPS
10.200.0.1
        |
        | RouterOS API TCP 8728
        v
Router API / Agent
```

Router WireGuard:

```text
10.200.x.x/32
```

Controller:

```text
10.200.0.1/32
```

Public WireGuard endpoint:

```text
wg.ispsolutions.co.ke:51820
```

The web application remains:

```text
https://ispsolutions.co.ke
```

Do not use the main web hostname as the WireGuard endpoint.

---

# 2. No MikroTik Certificate Dependency

This requirement is mandatory.

Do NOT:

* Install a MikroTik CA certificate.
* Create a CA certificate.
* Create a router certificate.
* Import certificates.
* Require RouterOS CA-store configuration.
* Use `check-certificate=yes`.
* Require API-SSL.

The agent's HTTPS bootstrap/fetch must use:

```routeros
check-certificate=no
```

WireGuard is the trusted management channel.

# 5. WireGuard Interface

Create or reconcile:

```text
wg-ispsolutions
```

Do not blindly rename unrelated WireGuard interfaces.

If an existing known legacy ISP Solutions/Gridline interface exists, it may be migrated safely.

Do not rename arbitrary interfaces.

Recommended:

```routeros
:if ([:len [/interface wireguard find where name="wg-ispsolutions"]] = 0) do={
    /interface wireguard add \
        name="wg-ispsolutions" \
        listen-port=13231 \
        private-key=$wgPriv \
        comment="ISP Solutions agent";
} else={
    /interface wireguard set \
        [find where name="wg-ispsolutions"] \
        private-key=$wgPriv \
        listen-port=13231 \
        comment="ISP Solutions agent";
}
```

# 6. WireGuard Peer

Create/reconcile the ISP Solutions controller peer.

Use the server public key as the primary identifier.

Do not identify the peer only by comment.

Required values:

```text
public-key       = server WireGuard public key
allowed-address  = 10.200.0.1/32
endpoint-address = wg.ispsolutions.co.ke
endpoint-port    = 51820
persistent-keepalive = 25 seconds
```

Example:

```routeros
:local peerId [/interface wireguard peers find where public-key=$srvKey];

:if ([:len $peerId] = 0) do={

    /interface wireguard peers add \
        interface="wg-ispsolutions" \
        public-key=$srvKey \
        allowed-address=10.200.0.1/32 \
        endpoint-address="wg.ispsolutions.co.ke" \
        endpoint-port=51820 \
        persistent-keepalive=00:00:25 \
        comment="ISP Solutions controller";

} else={

    /interface wireguard peers set $peerId \
        interface="wg-ispsolutions" \
        public-key=$srvKey \
        allowed-address=10.200.0.1/32 \
        endpoint-address="wg.ispsolutions.co.ke" \
        endpoint-port=51820 \
        persistent-keepalive=00:00:25 \
        comment="ISP Solutions controller";
}
```

# 7. WireGuard Address

Assign the router's unique overlay address:

```routeros
:if ([:len [/ip address find where interface="wg-ispsolutions" and address=$wgAddr]] = 0) do={

    :foreach a in=[/ip address find where interface="wg-ispsolutions"] do={
        /ip address remove $a;
    }

    /ip address add \
        address=$wgAddr \
        interface="wg-ispsolutions";
}
```

Do not blindly modify unrelated IP addresses on other interfaces.

Use a dedicated RouterOS group containing only the permissions required by the agent.

If the current ISP Solutions agent requires full RouterOS configuration access and the application has not yet implemented granular permissions, support:

```routeros

```

as the fallback.

The user must have:

```routeros

```

The user must be restricted to the WireGuard controller:

```routeros

```

Example:

```routeros

:if ([:len [/user find where name=$apiUser]] = 0) do={

    /user add \
        name=$apiUser \
        password=$apiPass \

    /user set \

        group="full" \
        address=10.200.0.1/32 \
        comment="ISPsolutions";
```

Do not use:

```text

```

# 11. API Firewall Rule

```routeros
        in-interface="wg-ispsolutions" \
        protocol=tcp \
        dst-port=8728 \
        src-address=10.200.0.1 \

        protocol=tcp \
        dst-port=8728 \
```

# 14. Critical Fetch Implementation

The agent must capture the result of `/tool fetch`.

Do NOT assume that no exception means failure.

Use:

```routeros
:local result [/tool fetch \
    url=("https://ispsolutions.co.ke/api/agent/script?token=" . $agentToken) \
    mode=https \
    check-certificate=no \
    http-method=get \
    output=file \
    dst-path="ispsolutions-pull.rsc" \
    as-value];
```

Then:

```routeros
:local status ($result->"status");
:local code ($result->"code");
:local downloaded ($result->"downloaded");
```

A successful fetch must be recognized as:

```text
status = finished
code = 200
downloaded > 0
```

Do NOT generate:

```text
HTTPS fetch failed
```

when:

```text
Download from ispsolutions.co.ke FINISHED
```

has already occurred.

# 15. Complete Agent Script

Generate the persistent script using this structure:

```routeros
/system script add \
name="ispsolutions-pull" \
policy=read,write,policy,test,password,sensitive \
source={

    :global ispSolLock;

    :if ($ispSolLock = true) do={
        :log warning "ISP Solutions agent already running";
        :return;
    }

    :set ispSolLock true;

    :do {

        :local fetchUrl ("https://ispsolutions.co.ke/api/agent/script?token=" . "<AGENT_TOKEN>");

        :log info "ISP Solutions agent: fetching configuration";

        :local result [/tool fetch \
            url=$fetchUrl \
            mode=https \
            check-certificate=no \
            http-method=get \
            output=file \
            dst-path="ispsolutions-pull.rsc" \
            as-value];

        :local status ($result->"status");
        :local code ($result->"code");
        :local downloaded ($result->"downloaded");

        :if ($status != "finished") do={

            :log warning ("ISP Solutions agent: HTTPS fetch failed status=" . $status);

            :set ispSolLock false;
            :return;
        }

        :if ($code != 200) do={

            :log warning ("ISP Solutions agent: HTTP request failed code=" . $code);

            :set ispSolLock false;
            :return;
        }

        :if ([:len [/file find where name="ispsolutions-pull.rsc"]] = 0) do={

            :log warning "ISP Solutions agent: download finished but file was not created";

            :set ispSolLock false;
            :return;
        }

        :local fileId [/file find where name="ispsolutions-pull.rsc"];
        :local fileSize [/file get $fileId size];

        :if ($fileSize <= 0) do={

            :log warning "ISP Solutions agent: downloaded script is empty";

            :do {
                /file remove $fileId;
            } on-error={};

            :set ispSolLock false;
            :return;
        }

        :log info ("ISP Solutions agent: downloaded " . $fileSize . " bytes");

        :do {

            /import file-name="ispsolutions-pull.rsc";

            :log info "ISP Solutions agent: configuration imported successfully";

        } on-error={

            :log warning "ISP Solutions agent: configuration import failed";

            :do {
                /file remove $fileId;
            } on-error={};

            :set ispSolLock false;
            :return;
        }

        :do {
            /file remove $fileId;
        } on-error={
            :log warning "ISP Solutions agent: unable to remove temporary file";
        };

    } on-error={

        :log warning "ISP Solutions agent: unexpected execution error";

    }

    :set ispSolLock false;
}
```

The backend must replace:

```text
<AGENT_TOKEN>
```

with the router-specific token during generation.

# 16. Do Not Scan Files Loosely

Do not use:

```routeros

}
```

to locate the downloaded script.

```routeros

```

This avoids accidentally importing another similarly named file.

# 17. Import Security

The downloaded `.rsc` must be treated as executable configuration.

The server-side endpoint must return only the intended ISP Solutions agent/configuration payload.

Do not allow arbitrary user-provided RouterOS commands to reach this endpoint.

The backend must validate:

* Router identity.
* Router ID.
* Agent credential.
* Tenant/platform authorization.
* Configuration version.

Do not expose arbitrary script-generation capability through an unauthenticated endpoint.

---

Never log:

```text

apiPassword
```

* Application logs.

# 31. Final Acceptance Criteria

The implementation is complete only when:

* RouterOS v7 enrollment is fully generated.
* No `owner=admin` dependency exists.
* The persistent agent executes under the generated configuration.
* Dedicated ISP Solutions API user is created/reconciled.
* Username can be derived from the WireGuard IP.
* User comment is `ISPsolutions`.
* API access is restricted to `10.200.0.1/32`.
* API is not exposed to WAN.
* WireGuard uses `wg.ispsolutions.co.ke:51820`.
* Router peer uses `allowed-address=10.200.0.1/32`.
* No MikroTik CA certificate is required.
* HTTPS fetch uses `check-certificate=no`.
* `/tool fetch` results are correctly interpreted.
* `FINISHED` + HTTP 200 is treated as success.
* Downloaded file is explicitly validated.
* File is imported only after successful validation.
* Temporary file is removed after successful processing.
* Agent lock cannot remain permanently stuck.
* Scheduler executes successfully.
* Enrollment is idempotent.
* Router identity and API connectivity can be verified.
* All generated-script dialogs have Autocopy.
* Autocopy copies the exact generated script.
* No secrets are written to logs.
* No unrelated ISP Solutions functionality is changed.

**Implement this as the complete RouterOS v7 enrollment/agent solution, not merely as a change to the error message.**
